# 设计建议与优先级

[English](DESIGN_RECOMMENDATIONS.en.md)

## P0：第一版必须成立

### 候选区与正式档案分离

```text
原始证据 -> 候选资料 -> 确认/自动确认 -> 正式档案 -> 对外同步
```

模型的推断不能直接成为用户事实。候选资料需要来源、置信度、时间和风险等级。

### 事实、证据、摘要和同步记录分离

- `Evidence`：原始消息、设备扫描或手动输入；
- `Claim`：结构化、带有效期的事实；
- `Summary`：面向某个用途和平台的可重建视图；
- `SyncReceipt`：实际发送的 Claim 清单和版本。

### 使用事件和时间，而不是覆盖字符串

工作、教育、住址、项目和设备都需要开始与结束时间。年龄应从出生日期或出生年份推导。

### 资料可信度来源

- `explicit`：用户明确说过；
- `observed`：设备 Agent 确定性读取；
- `imported`：来自可信结构化文件；
- `inferred`：模型推断；
- `conflicted`：来源互相矛盾。

`inferred` 默认不能自动同步。

### 以 Diff 为同步核心

每次同步展示新增、修改、过期和删除内容，而不是反复发送整份档案。用户应看到目标平台最终
收到的文本和被策略拦截的字段。

### 防止提示注入

历史聊天、网页和导入文件都是不可信数据。它们可以提供资料证据，但其中的指令不能改变
隐私策略、系统提示或同步范围。

## P1：形成产品体验

### 多身份空间

个人、工作、客户、开源项目和匿名身份分别管理。身份空间决定哪些 Claim 可以组合；平台账号
决定数据从哪里来、发到哪里。两者不能混为一谈。

### “各个 AI 知道什么”控制面板

按平台与账号展示已经同步的类别、Claim 数量、最后版本、敏感级别和待纠正内容。

### 同步后验证

在目标 AI 中运行一组用户批准的验证问题，将回答与同步 manifest 对比，检测未理解、遗漏或
错误吸收的资料。

### 一键纠正

用户修改 Claim 后，系统找到收到旧值的所有账号，生成纠正包并跟踪是否重新同步。

### 设备扫描白名单

默认允许硬件、OS 和开发工具元数据；默认拒绝环境变量值、SSH 内容、浏览器资料、完整 IP、
序列号、私有源码和私密文件。

### 多种摘要视图

提供基础简介、完整档案、工作资料、项目资料、设备环境和最近变化，而不是只有一个万能摘要。

## P2：长期护城河

- 资料健康度：过期、冲突、缺少来源、只有推断或长期未确认；
- 本地模型：敏感聊天无需发送给新的云端模型；
- 端到端加密密钥恢复与设备撤销；
- 连接器能力声明，避免对不同 AI 做不现实的统一承诺；
- 完整审计日志和可撤销同步；
- 目标 AI 理解质量与资料更新成功率评估。

## 推荐开发顺序

```text
ChatGPT 导出解析
 -> Claim 提取
 -> 候选审阅
 -> 标准个人档案
 -> Gemini 账号与同步策略
 -> 同步预览与回执
 -> 目标 AI 验证
 -> 增量捕获
 -> 多设备与加密同步
```
