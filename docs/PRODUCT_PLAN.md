# 产品计划

[English](PRODUCT_PLAN.en.md)

## 产品定义

ContextVault 是一个跨 AI 的个人记忆同步层。它回答的不是“我的聊天记录在哪里”，而是：

> 不同 AI 分别知道我什么，哪些仍然有效，哪些可以共享，如何让它们自动保持一致？

系统从聊天、官方导出、本地设备和用户输入中提取结构化资料，维护一份标准个人档案，
再把经过策略过滤的版本同步到 Gemini、Claude、ChatGPT 或未来的其他工具。

同一平台的多个个人、工作或客户账号必须分别识别。资料通过明确的
`来源账号 -> 身份空间 -> 目标账号` 路由流动，默认不跨空间混合。

## 典型场景

### 场景一：ChatGPT 到 Gemini

用户已经与 ChatGPT 对话两年。系统导入历史记录，发现并整理年龄、学校、专业、工作、
所在地、语言、回答偏好、项目和目标。用户集中审阅一次后，系统生成 Gemini 可使用的
资料摘要。以后新信息发生变化时只同步增量。

### 场景二：设备与开发环境

用户有 MacBook、Windows 台式机、VPS 和手机。本地 Agent 自动记录型号、系统版本、
主要软件、开发工具、项目目录和允许共享的配置。当用户问 AI 如何部署或排错时，目标 AI
已经知道正确的设备环境。

### 场景三：信息变化

旧对话说用户在 A 公司，新对话说已经加入 B 公司。系统不会同时把两者当作当前事实，
而是结束 A 公司的有效期、把 B 公司标为候选当前工作，并在必要时请求确认。

## 用户资料范围

第一阶段支持：

- 身份与基本信息：姓名、年龄、生日、语言、时区、所在地；
- 教育：学校、专业、学历、时间段、课程和证书；
- 工作：公司、职位、团队、职责、工作方式和时间段；
- 偏好：回答风格、沟通、写作、代码、饮食、旅行和购物偏好；
- 能力与目标：技能、正在学习的内容、长期目标和计划；
- 项目与决策：项目、技术栈、当前状态、关键决定和待办；
- 人际关系：用户主动确认的重要人物及关系；
- 设备与环境：硬件、系统、软件、开发环境、网络角色和非敏感配置；
- 重要事件：搬家、换工作、毕业、购买设备等带时间属性的变化。

医疗、财务、法律、精确地址、身份号码等高敏感信息可以建模，但默认不自动跨平台同步。
密码、验证码、私钥、API key、Cookie 和 session token 永远不进入资料库。

附件采用引用模式：数据库只保存提供商账号、文件 ID、会话来源、元数据、状态和可选的用户批准
提取文本。原始文件继续由 ChatGPT、Gemini、Claude 等来源平台托管，ContextVault 默认不提供
对象存储或独立附件备份。

## 核心闭环

```text
采集 -> 提取候选 -> 归一化 -> 冲突与时间判断 -> 用户策略/确认
  -> 标准个人档案 -> 目标平台摘要 -> 同步 -> 回执与变更历史
```

### 1. 采集

- ChatGPT、Claude、Gemini 官方导出；
- 浏览器扩展捕获用户当前打开的新增对话；
- CLI/本地 Agent 扫描设备信息；
- 手动表单、Markdown、JSON 和剪贴板；
- 后续可选日历、联系人、代码仓库和智能家居连接器。

### 2. 提取与归一化

系统把自然语言转换成带来源的 `Claim`，例如：

```text
实体：user
属性：employment.current.company
值：Example Corp
来源：ChatGPT conversation abc / message 123
置信度：0.96
状态：candidate
敏感级别：private
有效期：2025-03 至今
```

年龄不应长期保存为静态数字；优先保存出生日期或出生年份，再按时间推导年龄。工作、学校、
所在地和设备状态同样需要有效期。

### 3. 审阅与策略

不是每条资料都要求逐条确认。系统按风险分级：

- 低风险且明确表达：可自动确认；
- 一般个人资料：批量审阅；
- 推断、冲突或高敏感资料：必须确认；
- 凭证与秘密：直接拒绝保存。

### 4. 自动总结

同一份标准档案可生成：

- 100–200 字核心简介；
- 完整个人资料；
- 当前工作与技能摘要；
- 某个项目上下文包；
- 所有设备与开发环境清单；
- 自上次同步以来的变更摘要；
- 针对 Gemini、Claude、ChatGPT 能力定制的资料包。

### 5. 同步

每个目标平台拥有独立策略：允许哪些类别、最高敏感级别、最大长度、更新频率、是否要求
预览。浏览器扩展只在用户已登录且明确授权的页面中拉取当前对话、创建专用对话或写入资料；
不上传 Cookie，不在服务器模拟用户登录。自动拉取和自动推送分别按账号、route 开启并确认风险。

敏感信息采用三级策略：`block`（永不发送）、`ask`（每次确认）和 `allow`（在明确范围内
自动同步）。策略按目标平台和资料类别设置，而不是一个全局开关。`secret` 级别不允许配置
为 `allow`。

## MVP

### MVP 1 — ChatGPT 个人资料提取器

- 解析 ChatGPT 官方导出；
- 提取身份、教育、工作、所在地、偏好、技能、项目和设备候选；
- 展示来源、置信度、冲突和时间；
- 用户批量确认；
- 输出标准 JSON 和可读 Markdown 档案。

验收：用户在 15 分钟内从多年聊天生成一份可用、可追溯的个人资料。

### MVP 2 — Gemini 同步

- 生成 Gemini 优化摘要；
- 提供同步预览和字段过滤；
- 通过用户触发的复制、文件导入或浏览器注入完成同步；
- 记录同步版本和变更。
- 对附件提供只同步引用、同步提取文本或用户触发即时转传三种模式。

验收：Gemini 能正确回答用户已确认的基础资料和偏好，且不会收到被禁止的字段。

### MVP 3 — 设备 Agent

- 扫描设备型号、CPU、内存、OS、包管理器、主要软件和开发工具；
- 配置允许同步的路径与设置；
- 多设备去重、最后在线时间和变更检测；
- 生成设备清单和排错环境摘要。

验收：AI 能区分用户的不同设备，并基于正确环境给出建议。

### MVP 4 — 增量自动同步

- 浏览器扩展捕获用户主动允许的当前对话，或在空白页创建低置信度资料探测对话；
- 增量提取和变化检测；
- 低风险字段按策略自动同步；
- 冲突和敏感变化进入审阅队列；
- 创建或复用目标平台专用对话，并用持久回执避免不确定发送被重复执行；
- 端到端加密多设备同步。

## 还应考虑的后续能力

- **关系与家庭图谱：** 只记录用户主动确认的重要关系。
- **时间线：** 展示教育、工作、居住、设备和项目变化。
- **可撤销同步：** 知道哪条资料发给了哪个平台，并生成删除/纠正指令。
- **多身份模式：** 个人、工作、某个客户或匿名身份分别管理。
- **多账号路由：** 同一平台的多个账号分别管理来源、授权、同步回执和纠正任务。
- **情境视图：** 只把与当前任务相关的资料发送给 AI。
- **被遗忘权：** 本地删除、远程纠正请求、同步墓碑和备份清理。
- **资料健康度：** 提醒长期未确认、冲突、可能过期或缺少来源的资料。
- **无需 LLM 的规则提取：** 对设备和明确字段优先使用确定性解析。
- **可选本地模型：** 敏感资料提取无需发送到云端模型。
- **同意记录：** 保存用户看到的风险提示版本、资料类别、目标平台、选择和撤销时间。
- **可选外部备份：** 后续可连接用户自己的 S3、WebDAV 或 Drive，但不作为默认附件存储。

## 成功指标

- 提取出的已确认资料准确率达到 95% 以上；
- 90% 以上的资料可追溯到原始消息或设备扫描；
- 从导入到首份 Gemini 资料包不超过 15 分钟；
- 增量同步时需要人工处理的候选低于 20%；
- 不保存任何凭证类秘密；
- 用户能清楚回答“哪个平台知道我的哪些信息”。

## 产品原则

1. 标准档案是真相来源，聊天不是。
2. 自动化程度由风险决定，不是一律自动或一律手动。
3. 新信息必须能使旧信息过期，而不是只追加。
4. 所有跨平台写入都可预览、追踪和撤销。
5. 设备配置与用户资料属于同一档案，但采用不同采集和敏感策略。
6. 默认本地处理；服务器只做端到端加密同步。
7. 免责声明用于知情同意，不用于绕过安全控制或把所有责任转移给用户。
